## 💭 My Reflection

Throughout this laboratory activity, I learned how automation can make cloud management easier and more reliable. When managing hundreds of cloud servers, performing tasks manually would take a lot of time and increase the chances of making mistakes. Automation allows administrators to run scripts and schedule tasks, such as backups, without having to repeat the same commands on every server.

However, I also learned that automation can be dangerous if it is not handled carefully. For example, a destructive typo in a script scheduled to run on 1,000 servers could delete important files or affect many systems at once. This is why scripts should be checked and tested before being used on multiple servers.

Writing a Bash script in this activity was different from creating a Docker Compose YAML file in Mission 6. With Bash, I wrote commands to perform tasks in sequence, such as creating a backup folder and compressing application data. In Docker Compose, I used YAML to define and manage services and their configurations. Both tools help simplify cloud operations, but they serve different purposes.

Looking back at my GitHub repository from Laboratory 1 to Laboratory 9, I can see how my understanding of cloud computing has grown. At first, I was mainly learning about cloud infrastructure and basic commands. As I completed more activities, I explored containers, storage, deployment, monitoring, security, and automation. I now understand that cloud computing involves more than just running applications; it also requires maintaining, protecting, and managing systems properly.

Among the different roles, I enjoyed the **Cloud-Native Engineer** role the most because I found working with Docker and containers interesting. I liked learning how applications can run in isolated environments and how containers make deployment more manageable. Overall, these laboratory activities helped me gain practical experience and a better understanding of the responsibilities of a cloud engineer.
